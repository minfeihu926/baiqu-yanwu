# 百趣演武 自动抽牌

《明日方舟：终末地》「百趣演武」抽牌界面的自动化小工具：逐张抽牌，自动识别**点数（1–5）**和**花色（万/条/筒）**，按你选定的目标牌型判断，凑不出来就立刻「放弃挑战」重抽，凑够了就停手。

**不点「开始挑战」，不参与战斗。**

> 非官方工具，与鹰角网络无关，使用风险自负。

## 下载

到 [Releases](https://github.com/minfeihu926/baiqu-yanyu/releases) 下载：

| 文件 | 说明 |
|---|---|
| `baiqu_yanyu.exe` | 单文件版，自带 Python 和依赖，双击或命令行运行 |
| `baiqu_yanyu_win64_portable.zip` | 便携版，解压即用；单文件版被杀软误报时使用 |

单文件版首次启动会解压到系统临时目录，慢 1~2 秒。exe 未签名，Windows Defender 可能误报。

## 使用

1. 游戏用**窗口模式**运行（1280×720 / 1280×800 / 1920×1200 / 2560×1600 均可），进入「百趣演武」抽牌界面；
2. 先确认能正确识别（不点击）：

   ```bat
   baiqu_yanyu.exe --image 截图.png
   ```

   或直接截图当前游戏窗口看识别结果：

   ```bat
   baiqu_yanyu.exe --check
   ```

3. 正式运行，按提示选目标牌型：

   ```bat
   baiqu_yanyu.exe
   ```

4. 达成目标后脚本自动退出，手牌保留，你自己点「开始挑战」。

```bat
baiqu_yanyu.exe -p 顺子        # 也可以直接用命令行指定牌型
baiqu_yanyu.exe -p 同花 -r 20  # 最多跑 20 轮
```

运行期间脚本会独占鼠标，游戏窗口需要在前台，`Ctrl+C` 可随时中断。

### 从源码运行

Windows + Python 3.9+：

```bat
python -m pip install -r requirements.txt
python baiqu_yanyu.py
```

也可以双击 `run.bat`（会自动补依赖）。

## 目标牌型

| 牌型 | 编号/参数 | 达成条件 | 何时放弃 |
|---|---|---|---|
| 顺子 | `1` / `-p straight` | 抽满 5 张，其中出现四连（1-2-3-4 或 2-3-4-5） | 剩余张数不够补齐四连 |
| 同花 | `2` / `-p flush` | 已抽的牌**绝对同色**，凑到 4 张即停（不必抽满 5 张） | 出现第二种花色立即放弃 |
| 同花顺 | `3` / `-p straight_flush` | 抽满 5 张、五张同花色，且点数恰好是 1-2-3-4-5 | 花色不齐或点数重复即放弃 |
| 四条 | `4` / `-p four` | 抽满 5 张，有四张同点数（五条也算） | 剩余张数不够凑 4 张同点 |
| 葫芦 | `5` / `-p full_house` | 抽满 5 张，三张同点 + 两张同点 | 剩余张数不够凑 3+2 |
| 三条 | `6` / `-p three` | 抽满 5 张，有三张同点数 | 剩余张数不够凑 3 张同点 |
| 两对 | `7` / `-p two_pair` | 抽满 5 张，两个不同点数各至少两张 | 剩余张数不够凑成两对 |

判定采用**包含**语义：更大的牌型也算达成（例如目标是三条时，四条、葫芦、五条同样算中；目标是两对时，葫芦也算）。只要不是真的不可能，脚本就不会放弃。

## 参数

| 参数 | 说明 |
|---|---|
| `-p, --pattern` | 目标牌型（`straight`/`flush`/`straight_flush`/`four`/`full_house`/`three`/`two_pair`，也可写中文） |
| `-r, --rounds N` | 最多跑多少轮，`0` = 无限制（默认） |
| `--check` | 截当前窗口做识别，不点击 |
| `--image PATH` | 离线分析一张截图 |
| `--debug` | 打印每张牌的识别分数 |
| `--dump PATH` | 把脚本看到窗口画面存成 PNG（排查识别用） |
| `--hwnd 0x...` | 手动指定游戏窗口句柄 |
| `--version` | 显示版本 |

## 识别方式

- **卡槽**：用青色卡背做列投影找出 5 个等距卡槽，翻开后按等间距推算；没有卡背时按窗口比例用兜底位置（16:9 / 16:10 两套，已按真实截图校准）；
- **是否翻开**：取样框内同时满足「白底 > 20%」和「深色笔画 > 3%」，避免把翻牌动画中的空白卡面当成牌；
- **点数/花色**：模板是带白边的图块（`templates/r1.png`~`r5.png` 56×72、`s_wan/s_tiao/s_tong.png` 44×52），按卡牌高度缩放后在取框内**整幅滑动**做归一化互相关，再乘 0.8~1.2 五档缩放，最高分 ≥ 0.70 且领先第二名 0.05 才采信；
- **按钮**：按颜色找中心（抽牌=青色、放弃=红色、确认=黄色），点击前校验游戏窗口是否在前台；
- 放弃前复查 0.2s 一次；点抽牌后最多等 3s。
- 手牌已满但有牌没认出来时，直接放弃重抽（不会卡在找抽牌按钮）。

## 概率（粗略估算）

按点数、花色等概率独立估算，牌库实际张数（1–5 点分别为 6/5/5/5/8）会让数值略有出入：

| 牌型 | 单轮成功率 | 大约几轮出一次 |
|---|---|---|
| 同花 | 13.6% | 7 |
| 顺子 | 19.2% | 5 |
| 两对 | 35.2% | 3 |
| 三条 | 29.0% | 3.5 |
| 葫芦 | 6.4% | 16 |
| 四条 | 3.4% | 30 |
| 同花顺 | 0.05% | 2100 |

每轮最多 5 次抽牌，单次抽牌约 1.5~3 秒；配合「一不可能就放弃」，实际平均时间比轮数 × 5 次要短。

## 常见问题

**找不到游戏窗口**
运行 `python tools/probe_windows.py`，把输出发到 issue。脚本会按「类名 UnityWndClass + 标题含 Endfield」→「进程名 Endfield*.exe」→「Unity 窗口」匹配，最小化的窗口会自动还原。

**找不到抽牌按钮**
确认游戏停在抽牌界面、窗口完整在屏幕内、没有改 UI 缩放或使用滤镜；把 `--check` 的输出发到 issue。

**点击没反应**
脚本和游戏权限保持一致（游戏是管理员就用管理员运行脚本）；确认游戏在前台。

**提示「手牌区域被其它窗口遮住」**
控制台窗口正好压在游戏画面上（尤其是置顶的命令行）。把控制台移开或最小化，只留游戏可见，脚本会自动继续。

**提示「识别不确定」**
说明某张牌的点数或花色没认准。用 `--debug` 再跑一次，把分数和截图发到 issue，补模板即可。

**跑很久**
同花顺本来就稀有（约 1/2100 轮），属于正常。

## 已知限制

- 只处理第一轮，不点开始挑战；
- 依赖当前游戏 UI 的布局与配色，大版本更新后可能需要重新校准模板与 `BTN_SPECS`；
- 仅支持 Windows，且游戏需窗口化运行（独占全屏时截图可能拿不到画面）。
